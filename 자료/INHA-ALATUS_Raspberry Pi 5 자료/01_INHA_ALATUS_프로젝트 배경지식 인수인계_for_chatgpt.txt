INHA ALATUS — Raspberry Pi 5 개발환경 배경지식/인수인계 문서
작성 기준일: 2026-10-08 (Asia/Seoul)
문서 목적: 다른 GPT 세션에 그대로 붙여넣어 현재 시스템의 결정사항, 설치 목적, 진행 순서, 미확정사항을 전달한다.
상태: 환경 구축을 위한 계획/가이드. 실제 Raspberry Pi에서 설치가 완료됐거나 검증됐다는 의미가 아니다.

[0. 새 GPT에게 요청하는 행동]
이 문서를 프로젝트 최신 인수인계 정보로 받아들이고, Raspberry Pi 5 관련 후속 요청에 답할 때 먼저 현재 상태를 확인한 후 이어서 안내하라. 기존 설명과 충돌하는 경우 이 문서의 최신 결정사항을 우선한다. 하드웨어 사양이나 소프트웨어 버전이 아직 확인되지 않은 부분은 확정했다고 가정하지 말 것. 특히 사용자가 실제 터미널 출력을 붙여넣었다면 그것을 최우선 진단 증거로 사용한다. 이미 정상 설치된 OS·Docker·Python·카메라 패키지를 불필요하게 다시 설치하거나 삭제하지 말 것.

[1. 프로젝트 범위와 목적]
프로젝트명: INHA ALATUS.
개발 개념: 사출/공중분리 → Wing-Folding 주익 전개/고정 → 고정익 비행 → Vision 기반 회수.
이번 범위에서 장거리 Waypoint/Loiter/YOLO 정찰은 핵심 개발 대상이 아니다.
Recovery에서는 회수망 자체를 YOLO로 인식하는 옛 구조를 폐기하고, 덜 촘촘한 Net 뒤에 놓인 양궁 과녁(Archery Target)을 검출·추적하며 Net이 기체를 물리적으로 포획한다.
'보는 대상 = 양궁 과녁', '잡는 구조 = Recovery Net'.

[2. 항전/컴퓨팅 최신 Baseline]
- FC: Pixhawk 6C (Pixhawk 6C Mini가 아님).
- Autopilot: PX4.
- Onboard Companion 우선 검토: Raspberry Pi 5.
- Vision 가속: Raspberry Pi AI HAT+ / Hailo 계열. 정확한 HAT 모델(8, 8L, AI HAT+ 2 등)은 아직 확인 전이므로 모듈별 설치 명령을 구분한다.
- 개발/시뮬레이션 PC: Ubuntu 22.04 + ROS 2 Humble 기반; PX4 SITL/Gazebo는 주로 PC에서 수행.
- Pi 5 실제 부팅 OS: Raspberry Pi OS 64-bit 하나. Ubuntu는 듀얼부팅이 아닌 Docker 안의 Ubuntu 22.04 ARM64 userspace.
- YOLO Training: 데스크톱 GPU에서 수행. Pi 5는 학습 모델 Inference만 수행.
- Ground QGroundControl Telemetry 및 Pilot RC Receiver: Raspberry Pi를 거치지 않고 Pixhawk 6C에 직접 연결한다. Pi/ROS 장애 시 수동개입 경로는 독립적으로 유지해야 한다.
- Vision에서 Servo PWM 직접 출력 금지. Guidance는 고수준 명령으로 PX4에 전달, 실제 비행안정화/조종면/ESC는 PX4가 담당.

[3. 소프트웨어 책임 분리]
Raspberry Pi OS 64-bit Host:
  Camera/rpicam/libcamera → Hailo Driver/HailoRT → YOLO Archery Target Inference → Detection Metadata 송신
Docker(Container: Ubuntu 22.04 ARM64 + ROS 2 Humble):
  detection_bridge → /alatus/target_detection → target_tracker → mission → guidance → MAVROS
Flight Controller:
  MAVLink 2 → Pixhawk 6C/PX4 → Servo/ESC
정리: 'Pi OS/Hailo는 보고, ROS 2는 판단하고, Pixhawk/PX4가 날린다.'
MAVROS 설치는 ROS 기본 통신이 검증된 이후 Pixhawk Bench 통합 단계에서 추가.
모의 Detection에서는 std_msgs/String JSON으로 간단히 검증할 수 있지만 최종 운용은 alatus_msgs의 구조화된 ROS Message로 변경할 계획이다.

[4. 개발 역할]
DDD+EEE: Flight Control/Simulation (PX4, Gazebo, QGC, Fixed-Wing, Pixhawk 설정, RC/Failsafe).
FFF: ROS 2 Mission/Guidance (alatus_msgs, Mission State, Tracker/Guidance, Target Lost, Shadow Mode).
GGG: Onboard/System Integration (Pi 5, Pi OS, Hailo, Docker/ROS 배포, Host↔Container IPC, Pi↔PX4 통신, 로그/시간동기).
Vision 담당 별도: Archery Target 데이터셋, YOLO Training/Export, Hailo 추론, Detection 및 Tracking 일부.
Tracking 책임 경계(원시 Detection만 Vision이 낼지, 필터/Track State까지 Vision이 낼지)는 아직 TBD.

[5. 사용자 결정 — Swap]
64GB microSD 사용. 사용자는 '별도 Swap 파티션을 만들지 않겠다'고 결정함.
따라서 분할/리사이즈/swapoff/파티션 생성 작업을 이 가이드에 포함하지 않으며 기존 Pi OS 기본 Swap/zram 설정을 건드리지 않는다.
64GB 전체가 64GiB로 표시된다고 가정하지 말 것. 실제 가용공간을 df -h /로 확인한다.

[6. 목표 설치 목록 / 위치 / 순서]
A. Pi OS Host: OS/ARM64/RAM/용량/기존 Python/Docker를 먼저 확인.
B. Pi OS Host: python3, python3-pip, python3-venv, python3-numpy, git, curl, ca-certificates; Vision용 venv(필요시 --system-site-packages).
C. Pi OS Host: Docker Engine + Docker Compose plugin. 기존 설치가 정상이라면 유지; 미설치 시 Docker 공식 Debian arm64 저장소 이용(64-bit Raspberry Pi OS용 경로).
D. Docker: 공식 ROS 이미지 ros:humble-ros-base-jammy(ARM64 / Ubuntu Jammy 22.04)를 사용. 별도의 Ubuntu 설치 후 ROS 수동 설치는 필요 없음.
E. Dockerfile: colcon, rclpy, std_msgs, python3-numpy 등 ROS 개발 의존성 추가.
F. Docker Compose: host network(초기 localhost UDP 시험용), ROS_DOMAIN_ID=42(임시값), ROS_LOCALHOST_ONLY=1(초기 로컬 제한), 로컬 ros_ws bind mount.
G. 검증: Docker 확인 → ROS topic pub/echo → Pi Host의 Mock Archery Target JSON UDP 송신 → 컨테이너 Bridge → /alatus/target_detection topic echo.
H. 하드웨어 도착 후: Pi OS에서 카메라/AI HAT+ HailoRT를 공식 패키지 경로로 확인하고 사전학습 데모부터 실행.
I. 최종 비전: 데스크톱의 YOLO best.pt → 지원되는 ONNX export → 목표 Hailo NPU 및 호환 도구/후처리에 맞는 HEF → Pi 5 추론. .pt 복사만으로 Hailo 실행 가능하다고 가정하지 않음.
J. Bench 통합: MAVROS/GeographicLib 데이터, Pixhawk 6C 장치·포트·baud·FC 설정을 실측한 후 연결.

[7. 설치할 때 특별히 주의할 점]
- Raspberry Pi OS 버전과 Python 버전은 아직 사용자 실제 출력으로 확인되지 않았다. cat /etc/os-release, uname -m, dpkg --print-architecture로 검증할 것.
- Raspberry Pi AI 공식 문서는 2026-10-08 확인 기준 Trixie 64-bit를 요구한다. Bookworm 설치 기기에는 같은 Hailo 안내가 그대로 성립한다고 단정하지 않는다. OS를 무턱대고 full-upgrade하거나 교체하지 말고 하드웨어/공식 지원 조합 확인부터.
- AI HAT+(Hailo-8/8L): hailo-all / AI HAT+ 2(Hailo-10H): hailo-h10-all. 이 패키지들은 혼용 불가. HAT 제품 확인 전 일괄 설치 금지.
- Pi OS Bookworm 이후 시스템 pip 직접 설치(--break-system-packages, sudo pip) 지양. apt와 venv를 구분.
- ROS 공식 Docker 이미지의 Ubuntu/Python 버전은 Host Pi OS와 달라도 정상.
- ros:humble-ros-base-jammy는 Docker 공식 ROS 멀티아키텍처 목록에서 arm64v8로 확인됨.
- Docker Engine을 이미 설치했다면 재설치/패키지 삭제를 하지 않는다. Docker 공식 Debian 패키지와 배포판 docker.io 혼용 시 충돌 가능.
- docker group 가입은 일반적으로 root에 준하는 권한을 부여하므로 필수가 아니며 초기에는 sudo docker 사용.
- Docker Compose host network는 포트 분리를 약화시킨다. 초기 개발용. 실제 운용/원격 접속은 보안 및 통신 구조를 재검토.
- 컨테이너의 root로 bind mount Workspace에 작성하면 Host에 root 소유 파일이 생길 수 있음. 초기 가이드에서는 읽기/실행 위주; 팀 개발에서는 UID/GID 구성 필요.
- 'ROS_LOCALHOST_ONLY=1'은 네트워크에 있는 다른 PC의 ROS 노드와 연결할 때 변경이 필요함.
- ROS Domain ID 42, UDP 5005, JSON 필드, host network는 제안·모의검증용 설정이지 Freeze된 최종 인터페이스가 아님.
- Mock 데이터 timestamp_ns는 time.time_ns()의 예시일 뿐 카메라 취득시각이나 통합 Time Sync 규칙이 아님.
- 절대로 Python/YOLO/Mock Bridge를 실제 Servo/PX4 명령에 연결하지 않는다. Shadow Mode/Basic Flight/Failsafe 검증이 우선.
